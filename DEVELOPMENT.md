# Журнал разработки

Внутренний документ: как устроено, почему именно так, обо что уже споткнулись и что
делать дальше. Пишется для того, чтобы через полгода не пришлось выяснять всё заново.

**Дата последнего обновления:** 2 августа 2026 · текущая версия `2.1.0`

---

## 1. Что это за приложение

Учёт прогулов в университете. Человек открывает приложение и отмечает, был ли он на
паре, — сразу или задним числом. Приложение считает статистику и умеет выгружать
отчёт, который можно отдать на анализ ИИ.

Dart + Flutter, Android и Windows, всё хранится локально одним JSON-файлом.

### Доменные решения

Приняты в начале разработки, менять их без нужды не стоит — от них зависит модель данных.

**Пара** — упорядоченный элемент дня без времени. Время не хранится: для учёта прогулов
оно не нужно, а поддерживать тайм-слоты дорого.

**Дни** — Пн–Сб. Воскресенья в расписании нет.

**Недели** — номера 1–40, неделя 1 нечётная. Неделя 1 — та, в которую попадает
1 сентября (может начинаться в конце августа; дни до 1 сентября показываются пустыми).
**На каникулах нумерация останавливается**: календарная неделя, чей понедельник попал
в каникулы, пропускается и номер не увеличивает.

**Чётность** определяет базовое расписание: у чётных и нечётных недель они разные.

**Консультации** — пары с префиксом `#`. В прогулы не идут вообще; считается только,
сколько раз ты на них пришёл.

**Полный пропущенный день** — правило описано в
[README](README.md#как-считается-полный-пропущенный-день). Ключевое: «всё сдал»
приравнено к отменённой паре, то есть такие пары просто выпадают из подсчёта,
а не делают день посещённым.

**Хранение** — только локально. Никаких серверов и аккаунтов. Перенос между
устройствами — вручную через экспорт/импорт.

## 2. Архитектура

Чистое ядро без интерфейса + UI поверх него.

```
lib/
├── main.dart                    оболочка, нижняя панель, физика свайпа
├── app_state.dart               состояние приложения, уведомление страниц
├── core/                        логика, не знает про интерфейс
│   ├── models.dart              статусы, типы занятий, разбор строки пары
│   ├── calendar.dart            номера недель ↔ даты, чётность, каникулы
│   ├── resolver.dart            какие пары в конкретный день + отметки
│   ├── stats.dart               статистика, правило «полного дня», Markdown-отчёт
│   └── store.dart               модель данных и JSON-хранилище
└── ui/
    ├── theme.dart               палитра, размеры шрифтов, общие виджеты
    ├── status_menu.dart         поле и меню выбора статуса пары
    └── pages/
        ├── stats_page.dart      статистика, кольцевая диаграмма на CustomPainter
        ├── schedule_page.dart   расписание, протягивание за край
        └── settings_page.dart   настройки, импорт/экспорт, сброс
```

~2400 строк Dart. Состояние — один `ChangeNotifier` (`AppState`), передаётся страницам
явно; сторонних менеджеров состояния нет намеренно, приложение для них слишком мало.

### Формат данных

```jsonc
{
  "academic_year_start": 2025,          // год, в котором 1 сентября
  "breaks": [                            // каникулы: нумерация недель стоит
    {"start": "2025-12-29", "end": "2026-01-11"}
  ],
  "base_schedule": {
    "odd":  {"mon": [{"name": "Математика", "kind": "lecture", "consultation": false}]},
    "even": {"mon": []}
  },
  "overrides": {                         // правка конкретного дня
    "2026-05-11": [{"name": "Химия", "kind": "practice", "consultation": false}]
  },
  "marks": {                             // отметки посещаемости
    "2026-05-11": [
      {"subject": "Химия", "status": "skipped", "consultation": false, "kind": "practice"}
    ]
  },
  "last_week": 21,
  "swipe_pages": true
}
```

Отметка хранит **снимок** названия, типа и признака консультации. Сделано намеренно:
если потом поправить расписание, старые отметки и отчёт останутся корректными.

Файл экспорта расписания содержит только `academic_year_start`, `breaks` и
`base_schedule`. Импорт перезаписывает эту «основу» и **не трогает** накопленные отметки.

## 3. Жесты — почему сделано именно так

Самая проработанная часть приложения, на неё ушло больше всего времени.

### Свайп между страницами

Стандартная физика Flutter для страниц (`PageScrollPhysics.spring`) намеренно тяжёлая:
масса 80, жёсткость 100. Палец отпускаешь — страница ещё долго доезжает, выглядит
долистанной, но не долистана, и следующее касание перехватывается ею вместо прокрутки.

Поэтому задана своя пружина:

```dart
// lib/main.dart
final snappySpring = SpringDescription.withDampingRatio(
  mass: 0.26,      // вместо 80
  stiffness: 820,  // вместо 100
  ratio: 1.15,     // чуть передемпфировано, чтобы не было отскока
);
```

Эти три числа — единственные ручки настройки ощущения. Переход по кнопке нижней
панели живёт отдельно и равен 130 мс.

**Свайп отключаемый** (`Настройки → Интерфейс`). При выключении подставляется
`NeverScrollableScrollPhysics` — страницы остаются, листаются только кнопками.

**Заминка в начале жеста.** `PageView` по умолчанию не держит соседние страницы
построенными и создаёт их ровно в момент начала перетаскивания. Страницы тяжёлые
(списки строятся целиком, много выпадающих списков), отсюда микрофриз. Лечится
`allowImplicitScrolling: true` — соседи строятся заранее и остаются живыми.
Побочный плюс: состояние страниц перестало сбрасываться при переключении.

### Смена недели протягиванием

Список дней использует **упругую физику** (`BouncingScrollPhysics`), а не стандартную
для Android. Причина: при clamping-физике список вообще не сдвигается за край, поэтому
протягивание нельзя ни увидеть, ни отмотать назад — двигать нечего.

Прогресс жеста считается **не по накопленным событиям, а по фактическому смещению
списка за границу** (`pixels - maxScrollExtent`). Поэтому индикатор ведёт себя
предсказуемо: тянешь дальше — растёт, ведёшь палец назад — уменьшается, отпустил —
уезжает вместе с отпружиниванием.

Порог срабатывания — 75 px (`overTrigger` в `schedule_page.dart`).

Смена недели происходит **только пока палец на экране**: у инерционного отскока
`dragDetails` пуст, и такие события пропускаются. Иначе неделя менялась бы сама после
броска списка.

Плата за упругость: обычная прокрутка стала «как на iPhone» — с отпружиниванием
у краёв. Без этого протягивание невозможно в принципе.

## 4. Грабли

### Сборка Android

**Шаблон Flutter приносит Kotlin 1.8.22** — слишком старый для современных плагинов.
Поднят до 2.1.0 в `android/settings.gradle.kts`.

**Версию NDK нужно фиксировать явно** — плагины требуют `27.0.12077973`, шаблон ставит
другую. Прописана в `android/app/build.gradle.kts`.

**`--build-number` обязан расти** от сборки к сборке, иначе Android не поставит APK
поверх предыдущего как обновление.

**Демон Gradle держит папку `build`** — при попытке переместить или удалить получаешь
`Permission denied`. Убить процесс `java` перед файловыми операциями.

### API-мелочи

| Ожидание | Реальность (Flutter 3.29) |
|---|---|
| `FilePicker.platform.pickFiles()` | в `file_picker` 11 методы **статические**: `FilePicker.pickFiles()` |
| `DropdownButtonFormField(initialValue:)` | `value:` |
| `Switch(activeThumbColor:)` | `activeColor:` |

`FilePicker.saveFile()` на десктопе возвращает путь, но файл не всегда пишет сам —
после вызова проверяем и дописываем содержимое вручную.

### Интерфейс

**Штатный `DropdownButton` раскрывается 300 мс** — с разворачиванием списка по
высоте и подсветкой выбранного пункта. На странице расписания таких полей десяток,
и ожидание читается как «залипло». Поэтому меню статуса своё
(`lib/ui/status_menu.dart`): `PopupRoute` с проявлением за 80 мс, из анимации —
только прозрачность, позиция считается делегатом (под полем, а если снизу не
помещается — над ним). Заодно ушёл `FormField` с фокус-нодой на каждую пару:
теперь это обычный `InkWell`, а содержимое меню строится только при открытии.

**SafeArea обязателен** — иначе контент заезжает под строку состояния и вырез камеры.
Оставшийся сверху отступ — это сама строка состояния телефона, а не наш padding,
убирать его нельзя.

**Все три страницы используют `ListView(children:)`** — это не ленивый список, все
дочерние виджеты строятся сразу. Пока данных мало, это дешевле, чем `ListView.builder`,
но если расписание разрастётся — первое место, куда смотреть при тормозах.

## 5. Что дальше

### Проверить на устройстве

Ядро покрыто ручными прогонами, но вживую проверено не всё: импорт и экспорт файлов,
выбор диапазона каникул, выгрузка отчёта, полный сброс, Windows-сборка.

### Идеи без срока

- **Подпись своим ключом** — сейчас APK подписан отладочным. Нужно только для Play Store.
- **Уведомления** — напоминание отметить пары вечером
- **Быстрая отметка** — жест на карточке дня «весь день прогулял»
- **Статистика по неделям** — динамика, а не только сводка за всё время
- **Ленивые списки** — если страницы начнут тормозить на больших данных
- **Синхронизация между устройствами** — сознательно отложена: тянет за собой сервер
  или облачный аккаунт, что противоречит «всё локально»

## 6. Как работать с проектом

```bash
flutter pub get
flutter run
flutter analyze
```

Сборка:

```bash
flutter build apk --release --build-name=X.Y.Z --build-number=N
flutter build windows --release
```

Релиз:

```bash
git tag -a vX.Y.Z -m "SkipKOB_helper X.Y.Z"
git push origin vX.Y.Z
gh release create vX.Y.Z <файлы> --title "..." --notes-file notes.md
```

Windows-сборка выкладывается архивом целиком: рядом с exe лежат DLL и ресурсы,
по отдельности exe не работает.

**Коммиты** пишутся на русском, без трейлеров соавторства. Сообщение объясняет
**почему**, а не только что: через полгода полезна именно причина.

> полному пути либо добавить `C:\Users\Egor\flutter\3.29.2\bin` в PATH.
