## 1. Где мы сейчас

Приложение живёт в папке **`SkipKOB_Helper/`** — Dart + Flutter, релиз `2.0.0`.
Это то, что собирается и публикуется.

Рядом лежат две более ранние реализации, оставленные для истории:
`SkipKOB_Helper_Classic/` (Python + Flet) и `SkipKOB_Helper_Test/` (черновик Dart-версии).
В сборке и релизах не участвуют.

Что стоит проверить на устройстве: импорт и экспорт файлов, выбор диапазона каникул,
выгрузка отчёта, полный сброс, Windows-сборка.

## 2. Что это за приложение

Учёт прогулов в университете. Человек открывает приложение и отмечает, был ли он на
паре, — сразу или задним числом. Приложение считает статистику и умеет выгружать
отчёт, который можно отдать на анализ ИИ.

### Доменные решения

Приняты в начале разработки, менять их без нужды не стоит — от них зависит модель данных.

**Пара** — упорядоченный элемент дня без времени. Время не хранится: для учёта прогулов
оно не нужно, а поддерживать тайм-слоты дорого.

**Дни** — Пн–Сб. Воскресенья в расписании нет.

**Недели** — номера 1–40, неделя 1 нечётная. Неделя 1 — та, в которую попадает
1 сентября (может начинаться в конце августа; дни до 1 сентября показываются пустыми).
**На каникулах нумерация останавливается**: календарная неделя, чей понедельник попал
в каникулы, пропускается и номер не увеличивает.

**Чётность** определяет базовое расписание: у чётных и нечётных недель они разные.

**Консультации** — пары с префиксом `#`. В прогулы не идут вообще; считается только,
сколько раз ты на них пришёл.

**Полный пропущенный день** — правило описано в [README](README.md#как-считается-полный-пропущенный-день).
Ключевое: «всё сдал» приравнено к отменённой паре, то есть такие пары просто выпадают
из подсчёта, а не делают день посещённым.

**Хранение** — только локально, одним JSON-файлом. Никаких серверов и аккаунтов.
Перенос между устройствами — вручную через экспорт/импорт.

## 3. Архитектура

Обе версии устроены одинаково: чистое ядро без интерфейса + UI поверх него. Ядро легко
переносится между языками — так и появилась вторая версия.

```
ядро                       что делает
├── models                 статусы, типы занятий, разбор строки пары
├── calendar               номера недель ↔ даты, чётность, каникулы
├── resolver               какие пары в конкретный день + отметки
├── stats                  подсчёт статистики, правило «полного дня»
├── report                 Markdown-отчёт
└── storage                JSON-хранилище, экспорт/импорт

интерфейс
├── theme                  палитра и размеры шрифтов
├── stats_page             статистика
├── schedule_page          расписание
└── settings_page          настройки
```

Код приложения — `SkipKOB_Helper/lib/`, ~2400 строк Dart (отчёт живёт внутри `stats.dart`).

### Формат данных

Один и тот же в обеих версиях — файлы переносимы.

```jsonc
{
  "academic_year_start": 2025,          // год, в котором 1 сентября
  "breaks": [                            // каникулы: нумерация недель стоит
    {"start": "2025-12-29", "end": "2026-01-11"}
  ],
  "base_schedule": {
    "odd":  {"mon": [{"name": "Математика", "kind": "lecture", "consultation": false}]},
    "even": {"mon": []}
  },
  "overrides": {                         // правка конкретного дня
    "2026-05-11": [{"name": "Химия", "kind": "practice", "consultation": false}]
  },
  "marks": {                             // отметки посещаемости
    "2026-05-11": [
      {"subject": "Химия", "status": "skipped", "consultation": false, "kind": "practice"}
    ]
  },
  "last_week": 21,
  "swipe_pages": false
}
```

Отметка хранит **снимок** названия, типа и признака консультации. Сделано намеренно:
если потом поправить расписание, старые отметки и отчёт останутся корректными.

Файл экспорта расписания содержит только `academic_year_start`, `breaks` и
`base_schedule`. Импорт перезаписывает эту «основу» и **не трогает** накопленные отметки.

## 4. Грабли

Самая ценная часть документа. Всё перечисленное проверено на практике и стоило времени.

### 4.1 Flet: версия и API

**Flet жёстко закреплён на `0.28.3`.** В ветке 0.7x–0.85 API переписан: пропали
встроенные графики (`PieChart`, `BarChart`), изменились имена. Обновление ломает
приложение целиком. Обновляться только осознанно и целым заходом.

**`ft.Tabs` ломает соответствие вкладки и содержимого.** Если задать вкладке
`tab_content`, то вкладка 1 показывает содержимое страницы 3 — индексы разъезжаются
вдвое. Пустая подпись `text=""` даёт тот же эффект. **Работает только `text=" "`** —
пробел. Ловилось дважды, оба раза не сразу.

**Тип события протягивания — `"over"`, а не `"overscroll"`.** Из-за неверного имени
обработчик молчал, и смена недели протягиванием не работала в принципе. На это ушло
три подхода и одна ложная гипотеза («события вообще не приходят»), прежде чем
выяснилось в исходниках Flet.

**`ListView.spacing` игнорируется при `build_controls_on_demand=False`.** Не баг, а
структура: Flet выбирает между `ListView.separated` и обычным `ListView`, и во втором
`spacing` просто не передаётся. Симптом — слипшиеся карточки.

**`scroll_to(key=...)` молча ничего не делает**, если элемент ещё не построен (при
ленивом списке — почти всё, что за пределами экрана). Ошибки нет, просто тишина.

**Выпадающий список рисуется поверх всего экрана** и игнорирует безопасные зоны:
на телефоне залезает под строку состояния сверху и под кнопки навигации снизу. Список
из 40 недель был нечитаем. Решение — заменить на диалог.

**`indicator_thickness` не может быть 0** — падает на assert. Чтобы спрятать индикатор,
делать его прозрачным.

**Не ставить `visible=False` детям ListView** — `itemCount` считается по полному списку,
а индексация идёт по видимым, отсюда выход за границы.

### 4.2 Flet: физика жестов — потолок движка

**Главное ограничение, из-за которого появилась версия на Dart.**

`ft.Tabs` внутри — это `TabBarView` из Flutter. Когда отпускаешь палец, страницу
доводит `PageScrollPhysics.spring`: масса 80, жёсткость 100 — намеренно тяжёлая
пружина. Отсюда вязкий хвост: страница выглядит долистанной, но ещё едет, и следующее
касание перехватывается ею вместо прокрутки.

Наружу это не отдаётся ничем:
- `animation_duration` влияет **только** на переходы по нажатию, не на жест;
- `physics` в API Flet 0.28 отсутствует;
- у `Tabs` нет императивных методов — только свойство `selected_index`, а его установка
  в уже текущее значение ничего не делает.

**Что пробовали и почему не сработало:**

| Попытка | Результат |
|---|---|
| Крутить `animation_duration` | не влияет на жест |
| Своя анимация сдвига через Python | каждое движение пальца идёт по кругу Python↔Flutter — заметная задержка |
| Затухание вместо сдвига | без направления читается как подмена картинки |
| Мгновенное переключение (40 мс) | нет рывка, но и анимации нет вообще |
| Затухание + подъезд сбоку | «некрасиво» — не заменяет следование за пальцем |
| Убрать вмешательство в момент доводки | гипотеза не подтвердилась, проблема не в этом |

**Вывод:** внутри Flet задача не решается. Только Dart — там пружина задаётся одной
строкой.

**Ложный след, стоивший времени:** сначала было заявлено, что переход на Flet 0.86
решит проблему за счёт `ft.PageView`. Это неверно: пружина у `PageView` **та же самая**.
Разница только в том, что у `PageView` есть методы `jump_to_page`/`go_to_page`, которыми
доводку можно оборвать. То есть путь был бы обходным, а не прямым.

### 4.3 Сборка Windows (Flet)

**Нужен режим разработчика Windows** — Flutter создаёт символические ссылки для
плагинов, без него сборка падает с `Building with plugins requires symlink support`.

**Flutter 3.29.2 не знает Visual Studio 2026.** Определяет мажорную версию 18 и
откатывается к генератору «Visual Studio 16 2019», которого нет. Лечится правкой
в SDK:

```dart
// C:\Users\Egor\flutter\3.29.2\packages\flutter_tools\lib\src\windows\visual_studio.dart
return switch (_majorVersion) {
  17 || 18 => 'Visual Studio 17 2022',   // было: 17 =>
  _ => 'Visual Studio 16 2019',
};
```

После правки **обязательно** удалить `bin/cache/flutter_tools.stamp` и
`flutter_tools.snapshot`, иначе Flutter продолжит использовать скомпилированную
версию. При смене генератора чистить `build/` — CMake ругается на несовпадение с кэшем.

Правка живёт в папке Flutter, а не в проекте: если SDK перекачается, повторить.

**Демон Gradle держит папку `build`** — при попытке переместить или удалить получаешь
`Permission denied`. Убить процесс `java` перед файловыми операциями.

### 4.4 Сборка Android (Dart)

**Шаблон Flutter приносит Kotlin 1.8.22** — слишком старый для современных плагинов
(`share_plus` собран Kotlin 2.2). Поднимать в `android/settings.gradle.kts` до 2.1.0.

**Версию NDK нужно фиксировать явно** — плагины требуют `27.0.12077973`, шаблон ставит
другую. Прописывается в `android/app/build.gradle.kts`.

**Имя пакета обязано отличаться** от Flet-версии, иначе установить обе рядом нельзя:
для Android это одно приложение с разной подписью, установка падает.

### 4.6 Прочее

**SafeArea обязателен** — иначе контент заезжает под строку состояния и вырез камеры.
Убирать его нельзя: оставшийся сверху отступ — это сама строка состояния телефона,
а не наш padding.

**Окно на десктопе по умолчанию горизонтальное.** Приложение вертикальное, поэтому
размер задаётся явно: 430×900, минимум 360×600, по центру экрана.

**После `flet build` клиентский процесс переименовывается** в имя собранного
приложения (`skipkob_helper` вместо `flet`). Скрипты, ищущие процесс по имени, ломаются.

**Экземпляры приложения держат файлы сборки** — перед пересборкой закрывать все окна,
иначе `PermissionError` на `MaterialIcons-Regular.otf`.

## 5. Решения, которые обсуждались и были отвергнуты

**Непрерывная лента недель на весь год.** Идея: убрать переключение вовсе, показать все
40 недель одной прокруткой с разделителями. Реализовано и откачено — на телефоне
получилось плохо: долгое открытие (~9400 элементов строятся сразу), слипшиеся карточки
(см. грабли про `spacing`), промахи перемотки к запомненной неделе. Ленивое построение
проблему не решает: при нём Flutter не знает высот несозданных карточек и перемотка
попадает мимо.

**Вертикальные вкладки для недель.** Невозможно: у Flutter `TabBarView` нет
вертикальной ориентации в принципе.

**Горизонтальный свайп для смены недели.** Работал бы нативно, но занял бы ось, на
которой уже висит переключение страниц.

**Расширение на Dart поверх Flet.** Хирургический вариант: маленький компонент со своей
физикой, остальное остаётся на Python. Отвергнут в пользу полного переписывания —
поддерживать своё расширение при обновлениях Flet дороже.

## 6. Текущие идеи и что делать дальше

### Ближайшее

1. **Проверить Test на телефоне.** Главный вопрос — как ощущается свайп с новой
   пружиной. Если хорошо, дальше вопрос уже про переезд.
2. **Проверить Test функционально.** Ядро перенесено один в один, но на устройстве
   ничего, кроме сборки, ещё не проверялось: импорт/экспорт, выбор диапазона каникул,
   отчёт, сброс.
3. **Windows-сборка Test.** Проект создан с поддержкой Windows, но ни разу не собран.

### Если решаем переезжать на Test

- Перенести иконку и оформление окна на десктопе
- Настроить версионирование и подпись
- Сделать релиз, в котором Classic помечен как устаревший
- Решить судьбу `Test shed/` и примера `.conf` — они пока лежат у Classic

### Идеи без срока

- **Подпись своим ключом** — сейчас APK подписан отладочным. Нужно только для Play Store.
- **Уведомления** — напоминание отметить пары вечером
- **Быстрая отметка** — жест на карточке дня «весь день прогулял»
- **Статистика по неделям** — динамика, а не только сводка за всё время
- **Синхронизация между устройствами** — сознательно отложена: тянет за собой сервер
  или облачный аккаунт, что противоречит «всё локально»

## 7. Как работать с проектом

### Classic

```bash
cd SkipKOB_Helper_Classic
pip install -r requirements.txt
python main.py
flet build apk --project "SkipKOB_helper" --product "SkipKOB Helper" --org "com.arkorij" --build-version X.Y.Z --build-number N
flet build windows --project "SkipKOB_helper" --product "SkipKOB Helper" --org "com.arkorij" --build-version X.Y.Z --build-number N
```

`--build-number` обязан расти от сборки к сборке, иначе Android не поставит APK
поверх предыдущего как обновление.

### Test

```bash
cd SkipKOB_Helper_Test
flutter run
flutter build apk --release --build-name=X.Y.Z --build-number=N
flutter analyze
```

Flutter лежит в `C:\Users\Egor\flutter\3.29.2` и **не прописан в PATH** — вызывать по
полному пути либо добавить `C:\Users\Egor\flutter\3.29.2\bin` в PATH.

### Релизы

```bash
git tag -a vX.Y.Z -m "SkipKOB_helper X.Y.Z"
git push origin vX.Y.Z
gh release create vX.Y.Z <файлы> --title "..." --notes-file notes.md
```

Windows-сборка выкладывается архивом целиком: рядом с exe лежат DLL и Python-рантайм,
по отдельности exe не работает.
